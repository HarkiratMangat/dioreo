The door

the only page a stranger can reach

Every other surface is behind it, so it is the one page that must leak nothing — no hint of what data exists, no admin names, and crucially no message that confirms whether a particular account would have had access. All three states below say the same amount to a stranger. The scope list is not reassurance copy; it is literally what the OAuth request asks for, and it asks for identify and nothing else.

Broadcast

the only content pushed AT users

Announcements are the one thing a user doesn't ask for, so the questions are different: what is showing right now, in what order, and until when. The visual layer answers those two ways — Now showing renders the live set exactly as Discord does, in the order users receive it; Airtime puts every announcement on a time axis so overlaps and never-expiring posts are visible.

Heads up: “Season 7 is live” has no expiry and has been showing for 19 days. Announcements without an end date stay up forever.

One honest gap: models/Announcement.js has expiresAt but no start field — so "scheduled" above does not exist yet. Adding it is a one-line schema change, and by this repo's own rule it must land in the same change as the code that sets it, or Mongoose drops it silently. Flagged rather than drawn as if it already worked.

Operations

only what Discord can't already do

The temptation here is to rebuild /bot analytics in a browser. That would be waste — Health, Alerts, Usage and Timing already work, and a second copy is a second thing to keep true. So Operations does two things Discord genuinely cannot, and only summarises the rest.

Operations
4 admins · owner + 3 granted

Why these two and not the rest. The permission matrix replaces a Discord modal field where you type manage.draws,manage.calendar,bot as a comma-separated string and parsePermissionsInput rejects the whole thing if one token is wrong. A grid of the eleven real scopes can't be typo'd, and it shows what manage implies rather than making you remember. And the audit river offers revert, which does not exist anywhere today — /bot analytics' Changes page can only list, and markUndone merely flags a row when an in-memory undo is consumed, which dies on restart. A persisted inverse makes any change reversible later, from either surface. The source column is the point: one history, both surfaces.

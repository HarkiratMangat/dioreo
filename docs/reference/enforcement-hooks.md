# Enforcement hooks

**Created 2026-07-24 16:18 EDT** after Harkirat called out (correctly) that repeatedly editing the working agreement was damage control, not a cause-fix: rules kept getting ignored across sessions *despite being in context*, the agreement kept growing, and nothing structurally stopped recurrence. **The one rule that held this session was the changelog-at-commit HOOK** — it fired and got complied with, every time, because it's machine-enforced, not attention-dependent. So the strategy: **any mechanically-checkable rule becomes a hook in `.claude/settings.json`, instead of another line of prose in a doc I might skim.** Prose is for judgment rules; hooks are for checkable ones.

## 📉 The asymmetry lesson — measured 2026-07-28 14:15 EDT
**Enforce a rule for one artifact and not its siblings, and the unenforced ones quietly rot.** Across the last 22 releases: `CHANGELOG.md` **22/22**, `CHANGELOG-SUMMARY.md` **22/22**, `DEVLOG.md` **8/22 (36%)**. The only structural difference was that a `gh pr merge` hook checked the changelog and nothing checked the DEVLOG. The 14 misses were **not** trivial releases (they include the v3 structure design and the dev-bot Cloudinary safety fix), so the conditional was never *evaluated*, not evaluated and declined.

Three compounding causes, all now fixed — and all three generalise to any future hook:
1. **Asymmetric enforcement.** Same shape as `grep` 788 vs `rg` 4: prose loses to a session trying to finish. → a DEVLOG row now exists in the table above.
2. **A conditional rule.** "Write one *if* the work had real reasoning" is a subjective test evaluated at the worst possible moment. **Invert the default and require the SKIP to be spoken** — a skip you must say out loud is a decision; a silent one is an omission.
3. **⚠️ A partial check that feels total.** The changelog hook firing and passing read as *"the docs are handled"* while the DEVLOG sat untouched. **This is worse than no check**, because it suppresses the doubt that would have caught the gap. When writing a guard that covers part of a set, either cover the set or name what it does NOT cover, in the message itself.

## ⏱️ HOOKS RUN IN PARALLEL — and the cost model that follows (measured 2026-08-30 13:05 EDT)

**Proved by experiment, not inferred:** three probe hooks (two in one matcher group, one in its own) each slept 400ms. All three STARTED within 13.5ms of each other and overlapped ~400ms; total span 455ms, not 1,200ms. **Parallel both within a matcher group and across groups.**

🔴 **So the cost of a tool call is the SLOWEST hook, never the sum — and summing them is a real trap this measurement was written to stop.** Before the experiment this same session quoted "239ms per Bash call", which was a serial sum of parallel work and overstated the truth by ~4x.

| Measured | Value |
|---|---|
| Parallel wall clock, 16 Bash hooks | **54–63ms** |
| Serial sum of the same hooks | 186ms — **irrelevant, never the felt cost** |
| Slowest single hook (`branch-discipline-guard`) | 25ms |
| Per-hook floor | ~11ms, **entirely process spawn** (~3.2ms `bash -c` wrapper + ~3.5ms script + ~5.2ms `jq`) |
| **Edit path — only FOUR hooks** | **59ms** |

🔴 **A CLAIM THAT WAS WRITTEN HERE AND THEN FALSIFIED THE SAME HOUR — kept as the correction, because the reasoning error matters more than the number.** This paragraph originally read *"4 hooks cost the same as 16, so count does not matter"*, inferred from `Edit`(4 hooks)=59ms vs `Bash`(16 hooks)=57ms. **Both figures came from a harness that backgrounds every hook with `&` and then `wait` — it launches all N simultaneously and therefore has essentially ZERO dispatch spread. It is structurally incapable of measuring the effect of hook count.** An instrument that cannot detect X observed no X, and that was written down as "X does not exist". Third instance of [[feedback_instruments_inherit_their_authors_blind_spot]] in one session, and the only one where the blind instrument was built by the person quoting it.

**The controlled experiment that settled it** (12 sleeping observer hooks held CONSTANT, only the number of other hooks varied):

| Bash hooks registered | observed start-spread |
|---|---|
| ~28 | **38.8ms** |
| ~58 | **70.4ms** |

**+30 hooks → +31.6ms, near-linear at roughly 1ms per hook.** And the spread lands directly on wall clock, because the last hook to start still has to finish before the tool call proceeds (span tracked the spread in both runs: 572ms vs 593ms against a 500ms sleep).

⚠️ **Attribution caveat, stated rather than papered over:** the 30 dummies were added as 6 new matcher groups of 5, so hook count and group count varied together. The DIRECTION is established; whether the cost is per-hook (~1ms) or per-group (~5ms) is NOT distinguished by that design.

**So the working model is:**

    wall clock  ≈  slowest hook  +  ~1ms x (number of hooks)

At today's ~21 Bash hooks: 25ms + ~22ms ≈ **~47ms**.

🔴 **The practical consequence is NOT "delete hooks to go faster"** — a safety gate is worth vastly more than a millisecond. It is that **a new hook is not free: it costs ~1ms on every tool call of that type, forever.** Quote that price when hook number 22 is proposed, and keep new hooks cheap (one `jq`, early exit) so they never become the slowest one.

**Two optimizations that were considered and REJECTED, both for correctness, not effort:**

### `timestamp-check.sh` — a SIXTH defect: a placeholder time is not a bare date

### Standing rules this adds
1. **Every hook has a `<name>.test.sh`, enforced by `run-all-tests.sh`'s coverage pass.** `UNTESTED_OK` is an allowlist that can only shrink; it is **empty** and must stay so.
2. **Wire it, then verify it is wired.** A hook/test that nothing invokes is the default outcome, not the exception.
3. **Test through the same shell the hook uses.** Interactive aliases (`find`→`bfs`, `git`→`rtk`) make probes lie in the optimistic direction.
4. **Ask of every gate: at the moment this fires, can the thing it complains about still be prevented?** If not, it is documentation wearing a hook's clothes.
5. **A permanently-firing warning is a defect in the gate, not a fact about the repo.** When a check reports the same expected finding on every run, people stop reading the block it lives in — and it camouflages the next real finding. Fix it or suppress it; leaving it noisy is not the safe option it looks like.
6. **SUPPRESSED is a third state beside pass and fail, and it is only legitimate with all three of:** the check still runs and examines its items (so the vacuous-pass detector keeps watching it); it still prints its state every run (information withheld from the *findings*, never from the *reader*); and the suppression is gated so the **self-test still exercises the real logic**. Miss the third and the suppression disables its own failure test. Plus a **filed lift-trigger** — an exemption with no removal condition is permanent by accident.

### `timestamp-check.sh` — a SEVENTH defect: zero tolerance denied its own turn latency
*Found 2026-08-03 10:35 EDT (real incident), fixed 2026-08-06 22:00 EDT.* The impossible-timestamp compare was `[ "$d $hm" \> "$now" ]` — a zero-tolerance lexicographic string compare. `$now` is read once, at the top of the hook invocation; the content being checked was composed a turn or two earlier against a `[clock]` value that was already a minute or two stale by the time the bytes landed. So a perfectly honest `10:33` write denied against a clock that still read `10:32` — twice on 2026-08-06 (once during the morph-PoC session that filed it, once again in the session that fixed it), on writes whose content was correct both times. **Fix:** compare epoch seconds (`date -j -f '%Y-%m-%d %H:%M' "$d $hm" +%s`, BSD/macOS syntax) with a 180s grace window instead of raw strings. Still catches what the gate exists for — the original incident was stamps drifting **4.5 hours**, comfortably outside 180s — while no longer denying single-digit-minute drift from ordinary turn latency. Two new boundary tests added (`+1M` inside tolerance passes, `+4M` outside still denies).
**The general lesson, same shape as the bare-date branch's own history:** a check whose false-positive rate includes "denies its own normal operating latency" trains people to route around it. Zero tolerance sounds the most rigorous but is not the same as correct — the tolerance has to be wide enough to absorb the check's own measurement error (here: turn latency) while staying narrow enough to still catch the failure mode it was built for (hours-scale fabrication). See `docs/db-deferred-list.md`'s 🐞 Active Bugs entry (now resolved) for the full repro.

### `timestamp-check.sh` — an EIGHTH defect: the SEVENTH fix's own syntax was Mac-only
*Found + fixed 2026-08-07 10:05 EDT, before the SEVENTH-defect fix (above) had even shipped to `main`.* `date -j -f '%Y-%m-%d %H:%M' "$d $hm" +%s` is BSD/macOS date syntax — this project's dev machine, but not CI (`ubuntu-latest`, GNU date). GNU date rejects `-j`, the error was piped to `2>/dev/null`, and the `|| continue` treated the failure as "unparseable, skip" rather than surfacing it — so on CI the future- stamp gate parsed nothing, ever, and went **completely silent**: 46 of the test suite's 47 assertions failed there (`[SILENT]` where a `deny:` was expected) while all 47 passed locally on the Mac, because the Mac path never exercised the failure branch. ## 🚂 A gate that asks the SAME question every time decays into a checkbox (2026-08-08 12:50 EDT)

Harkirat, on `commit-completeness-sweep.sh`: *"your current hook is way too mechanical and restricted and doesn't properly make you check real world edge case angles... it's too hard of a guide-rail. like a train on tracks."*

**The structural diagnosis, which generalises past this one hook.** Its pass 3 asked "which of my five registered angles has no signature in this session?" — a question whose ANSWER SET is identical whether you renamed a variable or reflowed 44 files. A fixed question can only ever catch pre-enumerated classes, and it trains the reader to satisfy the list rather than think. Both real misses of the v2.63.0 session were outside the registry, and both were derivable only from the shape of that specific change:
- a deferred item whose stated scope was "comments, memory, CHANGELOG/DEVLOG, docs" shipped without memory, leaving **no textual trace at all** — no grep finds an omission nobody wrote down;
- changing wrap width silently invalidated every downstream heuristic that counted lines.

**The fix is three layers, cheapest first** — not a longer registry:
1. **Registry** — deterministic, change-independent, near-zero cost. Keeps derivation from being spent re-deriving "sweep `~/.config/dior`".
2. **Change-shaped demands** — computed FROM THE DIFF, each firing only when its property holds: an item left a tracking list ⇒ account for every noun in its original scope · a bulk/mechanical transform ⇒ name every heuristic that measured the property you changed · new enforcement ⇒ prove it can fail and check it against its own artifacts · a parsed file changed ⇒ run that parser before and after.
3. **Derivation** — a required sequential-thinking run, DETECTED in the transcript the same way tool signatures already are, with a fire counter that releases after two asks so it can never become a lock.

**What makes it un-tickable**, and this is the transferable part: the required output includes **at least one angle no automated check in the repo can see**, plus an explicit list of **what was NOT checked**. You cannot satisfy the first by running checks. A demand you can discharge by executing something will be discharged by executing something.

⚠️ **Two traps hit while building it, both already endemic here:** the derivation detector matches a string that appears in the hook's own SOURCE, so a `Write` of the file would have counted as a derivation (excluded file-writing tools — same shape as pass 3's `"name":"Bash"` scoping); and the first version of the sibling `memory-softwrap` check was written `async` while the runner calls `c.run()` synchronously, so it returned an unawaited Promise and **verified nothing while reporting a clean pass**. ⚠️ **An escape hatch nobody is told about is a trap with a workaround.** `timestamp-check.sh` implemented `TS-EXAMPLE` and `TS-DEADLINE` and mentioned neither in its deny message — so a legitimate citation of a documented future deadline was blocked twice, and the message instead gave advice its own header calls "simply wrong for scheduled events". ## 🟡 `defer-in-place-guard.sh` — the inverse of `outstanding-not-filed.sh` (added 2026-08-09 23:36 EDT, 15/15 tests)
PreToolUse on `Edit|Write`, warn-only. Fires when the text being WRITTEN instructs a future actor (`re-tag it`, `a future session should`, `whoever picks this up`, `revert this constant`, `fix this later`, `someone should`) — i.e. while the author has that very file open.

**Born from a real miss:** while editing `docs/db-deferred-list.md`'s memory-index item — removing the very premise that made it urgent — I wrote *"re-tag it and stop citing 'approaching read limit' as the reason"* INTO that item. Harkirat: *"you're literally correcting and updating it right now so why not [just] retag it yourself?"*

**Why it is NOT covered by `outstanding-not-filed.sh`:** that Stop hook catches *named but never filed*. This is the inverse — the item **was** filed, filed as someone elses job. It passes every existing gate because **a written-down deferral is indistinguishable from diligence.**

⚠️ **Scoped to `new_string`/`content`, never the file** — `db-deferred-list.md` is BUILT of legitimate deferrals and would match on every single edit. ⚠️ **Self-exempt by BASENAME** (the hook and its test carry every trigger phrase by construction); the test pins that a *similarly-named* file is still caught, so the exemption cannot rot into a substring hole. Legitimate deferrals stay silent by design — `deferred to`, `blocked on`, and neutral `[P3 · M]` filing language are all pinned as true negatives, because a guard that fires on normal tracker traffic gets ignored and then deleted.

⚠️ **Match commands with a REGEX, not a glob.** The first version used `*"git commit"*` and missed live on `git -C <path> commit` — and would have missed every `rtk git commit` too, which is most of them on this machine given the rtk rewrite hook. Caught only because the live trigger stayed silent when it should have fired.

## Added 2026-08-15 17:07 EDT — two guards from the /draw calculator design session

Both are **advisory** (`additionalContext`, never a deny), both TRACKED in `.claude/settings.json`, both carry a `.test.sh` wired into `run-all-tests.sh`.

- **`gate-truncation-guard.sh`** (PreToolUse/Bash) — fires when a gate (`npm test`, `docs:audit`, `docs:reflow`, a `scripts/*.test.js`) is piped straight into `tail`/`head` with no `$?` or `PIPESTATUS` capture. **Why:** a pipeline exits with its LAST command's status, and these gates print the ERROR block ABOVE the trailing summary — which counts checks that RAN, not checks that PASSED. So a truncated view reads exactly like a clean run. It hid a real `doc-frontmatter` failure for two commits in the very session that wrote this hook, despite the rule already being recorded in prose. Stays silent on the honest shape (`>/tmp/log; echo $?; tail`), because denying that would push work toward more noise.
- **`untracked-doc-guard.sh`** (PreToolUse/Bash) — fires when a docs gate runs while untracked `.md` files exist. **Why:** `reflow-prose.mjs` and docs-audit resolve their file list from `git ls-files`, so a brand-new document is invisible to both — and the gate reports a healthy count over the corpus it CAN see, indistinguishable from a genuinely clean run. A 1,000-line plan passed both gates, was committed on that basis, and only then failed on front matter and hard-wrapped prose. Staging is enough to make it visible; the hook goes quiet once the file is added.

**The pattern both follow:** a rule that had ALREADY been written down in prose, and was violated anyway by the same session that wrote it. That is this repo's stated trigger for promoting a rule to a hook.

## Two mechanical facts about how these hooks BEHAVE, measured 2026-08-30

⚠️ **Hooks run in PARALLEL, so a tool call costs the SLOWEST hook and never the sum** — but COUNT is not free: measured ~1ms of dispatch spread per hook, so ~21 Bash hooks ≈ 47ms on every call. **Quote that figure before adding one.**

⚠️ **`overwrite-guard` interrupts a clobber of an EXISTING UNTRACKED file, and `.remember/remember.md` is exactly that** — gitignored, and precisely what the guard protects. Its carve-out covers `/tmp`, `*/scratchpad/*`, `*.log`, `*.tmp` and nothing else. **Expect the prompt when writing a handoff; it is the guard working, not a failure.**

## 🔴 QUOTING A DETECTOR IS INDISTINGUISHABLE FROM TRIPPING IT — carry the escape token when you EXPLAIN a gate (2026-09-06 20:53 EDT)

Two hooks here scan the transcript for a pattern and both ship an escape token for text that QUOTES the pattern rather than producing it: the model-gate uses `MG-EXAMPLE`, the timestamp hook uses `TS-EXAMPLE`. Both tokens exist because writing ABOUT the thing kept tripping the check.

**On 2026-09-06 I hit it from the other side.** Explaining in chat that the model-gate had misfired, I quoted the derivation string it had matched — without the token. That sentence landed in the transcript as an ASSISTANT message, which is the one envelope the gate treats as authoritative, and it became the newest "derivation" for every subsequent prompt. **I made the gate fire on my own explanation of why it was firing.**

**Two separate false-positive sources, and only one was the tool's fault:**

| Source | Whose fault | Fix |
|---|---|---|
| An MCP tool result containing a stored raw prompt | The hook's — nothing can add a token to a server's output | Filter the envelope: exclude `"type":"tool_result"` |
| My own message quoting the pattern while explaining it | **Mine** — the escape exists precisely for this | Append the token to that line |

**How to apply.** Whenever you write a derivation string, a fabricated-looking timestamp, or any other scanned pattern INTO PROSE ABOUT THE CHECK, append its escape token on that line. ⚠️ **And check what the token is before assuming there is one** — `MG-EXAMPLE` and `TS-EXAMPLE` are named in the hooks' own headers, and the model-gate's header explicitly warns that a hook whose message quotes its own detector suppresses itself forever.

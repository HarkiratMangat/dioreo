Session 2 of the second pin batch ran across a night, with one agent paused at a checkpoint and resumed in the morning.

What it built: the attachment slots copied from Cloudinary into Mongo; the shared Manifest toolbar on every realm; History's local time, role widths, severity meters and Load older events; Broadcast's manifest, HeadsUp, announcement card and Changes ahead; Armory's weapon groups and Compare; and, through agent D, the New Build drawer and the Broadcast composer.

What it learned: the session-start thinking pass was skipped and Harkirat stopped it two thoughts in — the pass it then ran found that the plan's own order would never hand agent D the tokens it needed, that a worktree has no node_modules, and that the harness fixtures carried no slots. The first turn estimate (150–250) assumed one edit per turn; gather · one heredoc · one verify cut that by an order of magnitude. Two class names collided silently with older components (`.bcard`, `.bbar`) and only a duplicate-selector sweep after the merge showed it.

Draft written 2026-09-15 09:18 EDT; run it through `node scripts/devlog-add.mjs --desc "... (v3.85.0-pre)" --body-file` at the pre-merge checkpoint.

The pre-push pass found what the integration checks could not: agent D's New Build image upload ran inside the changeset's Mongo transaction with `overwrite: true`. A Cloudinary write is not rolled back, so an edit whose changeset failed later had already replaced the live image. Every check I had run was shaped around the surfaces the plan drew, and none looked at the operation core's contract. The fix is an `afterCommit` step that `commitSet` runs only once the transaction has committed, proven on dev by running the same probe against the old code (one upload on a rolled-back changeset) and the new (none). The same pass found the upload route's comment naming a server-wide body cap that does not exist.

**Harkirat's review, and the board that came out of it (added 2026-09-17 12:55 EDT).** He went over the dev portal himself and left 57 pins, 38 of them with crops. Almost none was a bug: they were judgements about hierarchy, rhythm, wording and motion that no gate in this repo can hold an opinion about, which is why they arrived as pins rather than as failures. The session that took them in wrote no portal code at all — it turned every pin that needed a decision into a drawn option on a design board running the portal's own code against the dev database, so that what he clicks is literally what gets built. Four boards were published before he closed one, and the thing that kept producing another round was not the difficulty of any single fix. It was that I kept fixing the level he pointed at: the badge motion took three rounds because I corrected the easing, then what was animated, then what the motion MEANT; an icon ring took three because I fixed one instance, then three parent selectors, then the class. The last of them — META's badge, rejected four times — only landed once the question changed from *which effect* to *what kind of claim is this badge making*, and the answer, that a bolt is a conductor and a conductor discharges, wrote the animation on its own.

The other lesson is about instruments. Forty-nine throwaway probe scripts were written across that session and not one of them found a defect that mattered; every real one came from cropping a render and looking at it, two were found despite a probe reporting clean, and two wrong JUDGEMENTS read off a downscaled crop reached him as findings before being retracted. The rule that came out of it is now an anchor: render and look first, and keep a probe for the questions an eye genuinely cannot answer — a sub-pixel baseline, a contrast ratio, whether a loop closes.
